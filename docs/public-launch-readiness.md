# webClx 公网发布与托管试用就绪清单

当前状态（2026-08-14）：webClx 1.8.11 已在 GitHub 公开，Release、源码归档、校验文件和本机下载中心均已验证；GitHub Discussions 和 7 天隔离托管试用候补表单已开放。客户托管实例、专用 DNS 和公开申请站仍未开放。本文件是上线门禁，不代表尚未解析的域名已经存在。

## 域名职责

| 建议名称 | 用途 | 可以暴露的内容 | 禁止内容 |
| --- | --- | --- | --- |
| `code.fpsq.xyz` 或公共 Git 托管地址 | 项目主页与源码仓库 | README、许可证、安全策略、issue、release | 私有工作区、运行日志、凭据 |
| `downloads.fpsq.xyz` | 公开只读发布物 | 指定的源码归档、校验文件、发布说明 | 管理导航、其它项目制品、上传/删除/刷新 API |
| `apply.fpsq.xyz` | 试用申请 | 最小申请表、隐私和试用条款 | 模型密钥、服务器密码、管理员登录 |
| `trial-<customer>.fpsq.xyz` | 单个受邀客户实例 | 该客户的登录页和独立 webClx 实例 | 其它客户数据、当前管理员实例 |

不要把 `fpsq.xyz:11112`、本机 `/downloads` 管理页面或一个公共 webClx 账号直接发给陌生用户。

## 公开下载入口

公开下载站应使用独立只读路由或静态对象存储，仅发布经过验证的白名单文件：

- `webClx-1.8.11-source.tar.gz`
- `webClx-1.8.11-source.tar.gz.sha256`
- 需要保留时同时提供最近两个旧版本的成对文件。

发布过程必须先写临时文件再原子改名。下载响应应支持 HTTPS、正确的长度、稳定文件名和合理缓存；下载页面显示版本、大小、SHA-256、来源提交和发布日期。

不得把内部 `/api/artifacts` 管理能力、所有项目的制品目录或本地 API 令牌暴露给公网。若复用 webClx 制品服务，反向代理必须只允许白名单下载 GET 路径，并阻断管理、刷新、上传和删除方法。

## 客户实例模板

每次开通前生成并记录：

```text
customer_id
hostname
os_user
app_dir
workspace_root
service_name
loopback_port
artifact_dir
backup_target
created_at
trial_expires_at
```

必须满足：

- `loopback_port` 只监听 `127.0.0.1` 或由主机防火墙/网络命名空间限制；webClx 1.8.11 会忽略 `WEBCLX_ADDR` 中的 loopback 主机并规范为 `0.0.0.0`，因此不能只依赖该环境变量实现源端口隔离；
- nginx/Caddy 通过独立主机名转发 HTTP 和 WebSocket；
- 每个实例生成独立登录凭据、本地令牌和会话密钥；
- 客户模型配置只存在于对应 OS 用户目录；
- systemd 单元设置资源限制和独立工作目录；
- 备份加密、分客户存放，并进行一次恢复验证；
- 到期脚本先禁用执行能力，保留 7 天只读导出，再删除实例和在线数据；
- 不复用当前管理员的 Cookie、密码、配置、工作区或制品目录。

## DNS 与 TLS

1. 为公开下载、申请入口和首位客户实例分别创建 DNS 记录。
2. 从公网解析并确认记录只指向预期服务器。
3. 使用有效证书；现有泛域名证书能否复用取决于私钥管理和部署边界，不能仅凭名称覆盖就复制私钥到不受控主机。
4. 配置 HTTP 到 HTTPS 跳转、HSTS（确认所有子域均支持 HTTPS 后再考虑 `includeSubDomains`）和现代 TLS。
5. 从外部网络验证证书链、主机名、WebSocket、登录重定向和源端口不可达。

## 上线验收

公开下载：

- 无登录即可访问明确发布的两个 1.8.11 文件；
- 重新下载的归档 SHA-256 为 `a020193f1145b9a01a3a9726c3ee8b467c69e5164b85b01c0f22c07971f7d35f`；
- 页面不显示其它内部项目或管理员操作；
- 桌面和 375px 手机页面无横向溢出、控制台错误或失败请求。

隔离试用：

- 客户 A 无法解析、访问或推断客户 B 的目录、端口、Cookie 和备份；
- 非登录请求只到登录页，不能访问工作区/API/WebSocket；
- 登录后完成“电脑建立会话 -> 手机恢复 -> 发送任务交接 -> 收到回复”的演示；
- 服务重启后 tmux 会话仍可恢复；
- 导出、只读、删除和备份清除流程经过一次测试；
- 日志中没有密码、Cookie、API key、本地令牌或会话密钥。

## 当前未满足项

- `trial.fpsq.xyz`、`downloads.fpsq.xyz` 和 `apply.fpsq.xyz` 当前没有 DNS 解析；试用候补暂由 GitHub Issue Form 收集。
- `fpsq.xyz:11112` 是现有管理员实例，禁止作为客户试用入口或共享管理员凭据。
- 美国候选宿主已于 2026-08-14 配置高容量日志轮转、journald 512 MB 上限和 hourly 检查，并清理 21 GB 可重建 npm 下载缓存；根分区复核为约 32% 使用、35 GiB 可用。实例计划器仍强制至少 12 GiB 空闲，但每客户磁盘配额尚未实施。
- webClx 1.8.11 强制服务绑定 `0.0.0.0:<port>`；每个客户实例必须先完成主机防火墙、网络命名空间或等效的源端口隔离，并从外部验证源端口不可达。
- 经营主体、支持/隐私邮箱、适用地区、支付与收据方式尚未填写，因此只能收集人工审核的免费试用候补，不能开放无人值守收费注册。
- 尚无经过验收的一客一实例自动开通、资源配额、只读到期、导出、备份恢复和彻底删除流程。
- `scripts/hosted-trial-instance.sh` 已能生成无凭据计划、systemd/nginx/iptables 模板，并对 ID、端口、磁盘、二进制、静态资源、DNS 和 TLS fail closed；真实 provisioning、到期只读、备份恢复与删除仍未实现，因此客户实例继续保持关闭。
- 公开仓库暂无经过脱敏审核的真实手机/桌面产品截图或演示视频；不得使用包含本机路径、内部 Agent、客户制品或凭据的运行截图。

上述任一关键项未完成前，可以公开技术文章和版本信息、收集候补申请，但不得声称已开放公网托管试用。
