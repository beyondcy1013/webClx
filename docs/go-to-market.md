# webClx 上市与收入验证方案

本方案用于开发者预览阶段。目标不是用“多 Agent”概念吸引泛流量，而是验证用户是否愿意为随时可恢复的远程编程工作台、隔离托管和部署支持付费。

## 首批客户与痛点

按成交可能性从高到低寻找客户：

| 客群 | 当前痛点 | webClx 的可验证价值 | 首个付费产品 |
| --- | --- | --- | --- |
| 独立开发者、小型外包团队 | 离开电脑后任务中断；手机 SSH 操作困难；多个 Agent 上下文分散 | 手机浏览器恢复持久终端；统一查看工作区；保留原生 Codex、Claude、DeepSeek Harness 上下文 | 7 天隔离托管试用，转个人托管版 |
| 同时使用多个 Harness 的重度用户 | 手工复制任务和 review 结果；容易让多个 Agent 同时改同一工作树 | 可确认的终端消息、回复路由和“一名写入者、其余只读 review”流程 | 自托管部署支持或专业托管版 |
| 有 Linux 服务器但不想维护工具链的开发者 | TLS、服务守护、升级、备份和恢复占用时间 | 独立实例、版本化升级、备份与恢复服务 | 一次性部署服务加月度维护 |
| 需要内网 AI 开发工作台的小团队 | 不愿把代码上传到新的 SaaS；又缺乏统一入口 | 自托管、原生终端、可审计部署边界 | 付费试点与商业许可评估 |

不要把“支持更多模型”当作主要卖点。用户购买的是任务不中断、手机能处理紧急事项、环境由自己控制，以及多工具交接少出错。

## 产品梯度

1. 免费自托管：AGPL 源码、版本化归档、校验文件和安全部署说明，用于建立信任并获得技术反馈。
2. 一次性部署服务：远程完成安装、TLS、备份和一次恢复演练。建议 CNY 299 至 699，按环境复杂度报价。
3. 隔离托管：一位客户一个实例。预览期沿用 CNY 49/129 与 USD 8/19 两档，但云主机和模型费用单列。
4. 小团队试点：先做需求评审和权限边界设计，不在当前单管理员实例上直接增加陌生成员。
5. 商业许可：只面向无法履行 AGPL 网络源码义务的组织，合同定价，不削弱社区版功能。

## 成本与定价门槛

每位客户的月度贡献毛利按下式记录：

```text
月收入 - 云主机 - 存储与流量 - 支付手续费 - 月支持工时 * 内部时薪
```

- 托管基础版只适合支持时间很少的用户；月支持超过 30 分钟就应迁移到专业版或调整价格。
- 不承诺无限终端、无限存储、无限备份或无限人工支持。
- 模型账号和 API 消耗由客户直接向模型提供方购买，webClx 不代充、不共享、不转售凭据。
- 前 10 名付费用户按月复盘真实成本；连续两个月贡献毛利为负的套餐停止新售。

## 7 天试用漏斗

```text
看到真实演示 -> 提交申请 -> 人工筛选 -> 独立实例邀请
-> 首日从手机恢复终端 -> 7 日内使用至少 3 天 -> 付费或导出删除
```

申请表只收集邮箱、地区、用途、Harness、预计存储和是否已有服务器，不收模型密钥。试用成功事件定义为“用户在手机上恢复一个已有终端并完成一次真实操作”，不能只统计登录。

首批采用人工邀请是有意的：在支付、隐私条款、自动隔离和删除流程没有验证前，不开放无人值守注册。

## 渠道与内容

| 渠道 | 适合内容 | 首要行动 |
| --- | --- | --- |
| GitHub Release | 可复现版本、安装、安全边界、变更记录 | 获取下载与 issue 反馈 |
| Show HN | 为什么保留原生 Harness 终端；技术取舍与真实限制 | 获取工程师反馈，不硬销 |
| Product Hunt | 60 至 90 秒手机实机演示、双语截图、明确试用入口 | 收集试用申请 |
| Indie Hackers | 从自用工具到托管服务的成本、定价和转化记录 | 找早期付费用户并公开复盘 |
| Dev.to / Hashnode | tmux 持久化、终端消息协议、安全部署教程 | 搜索流量与自托管采用 |
| Reddit | 只在版规允许的相关社区，以教程或问题复盘发帖 | 参与讨论，避免跨版复制广告 |
| V2EX / 掘金 / 开源中国 | 手机远程编程实测、部署过程、开源说明 | 获得中文用户反馈 |
| 少数派 / 知乎 / 即刻 | 有真实试用案例后讲移动工作流 | 扩大非纯后端开发者触达 |

所有渠道使用带来源标记的独立申请链接，记录 `source`、申请、开通、激活和付费。每周只优化转化最好的两条渠道，不以浏览量代替付费验证。

## 首批内容计划

1. 发布版本说明：功能、威胁模型、已知限制、源码归档与 SHA-256。
2. 录制一段未经剪辑的演示：电脑启动任务、关闭浏览器、手机恢复、向另一 Harness 请求只读 review、收到回复。
3. 发布技术文章：为什么选择持久 tmux 和终端消息，而不是重新实现一个 Agent Harness。
4. 邀请 10 位目标用户试用，逐一观察首次手机连接过程。
5. 匿名整理三份真实案例后再上 Product Hunt；不得虚构评价、收入、下载量或客户 Logo。

## 发布门禁

公开源码发布前必须有可访问的公共仓库或明确标注来源的版本化归档、许可证、安全策略和校验文件。托管试用开放前还必须同时满足：

- 独立 DNS 名称和有效 TLS；
- 每客独立 OS 用户、目录、服务、端口、工作区、凭据、制品和备份；
- 防火墙不暴露源端口；
- 可执行的导出、删除、恢复和事故响应流程；
- 已发布的隐私、服务、退款和支持边界；
- 申请入口不指向现有管理员登录页。

任一条件缺失时，只发布开源版并收集试用候补名单，不提供共享账号或裸端口体验。

## 两周执行节奏

| 时间 | 动作 | 通过标准 |
| --- | --- | --- |
| 第 1 至 2 天 | 发布源码包、校验文件、双语说明与安全限制 | 下载后可验证并本地运行 |
| 第 3 至 4 天 | 录制桌面到手机的真实演示 | 不泄露路径、历史或凭据 |
| 第 5 至 7 天 | GitHub/Show HN/V2EX 首轮发布 | 10 个有效对话或 5 份申请 |
| 第 8 至 10 天 | 人工开通首批隔离试用 | 80% 首日完成手机终端操作 |
| 第 11 至 14 天 | 访谈、修复激活阻力、提出付费 | 至少 2 个明确付款或拒绝理由 |

若两周内没有有效申请，先修改定位和演示；有申请但无法激活，先修产品；有持续使用但不付费，再调整套餐和价格。不要直接用降价掩盖前两类问题。
