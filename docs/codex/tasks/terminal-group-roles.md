# 终端分组角色

## 当前合同（2026-11-11）

用户指定的位置是“终端管理 / 编辑群组”的终端角色下拉。该下拉及新建终端加入群组时均支持四种角色：

| API 键 | 持久化显示名 | 职责与图标 |
| --- | --- | --- |
| `super_admin` | 超级管理员 | 👑，组内最高负责人，统筹计划、派发任务、协调普通管理员及最终裁决 |
| `manager` | 普通管理员 | 🔱，金色权杖式统率，负责日常计划、分工、验收与推进；有超级管理员时服从其协调 |
| `executor` | 执行者 | 🚀，执行已授权任务；默认固定火箭，仍支持用户显式选择随机方案或自定义 Emoji |
| `reviewer` | 复核者 | 复核与验收 |

终端角色保存在会话 `group_role`，与 WebUI 登录身份及 Linux 用户权限分开；不能以设置页显示皇冠替代终端下拉选项。角色本身不赋予额外系统或 API 鉴权权限。

终端列表中角色图标、项目图标在前，文本按 `[群组名] [工作状态] 终端名` 展示，群组名与后续字段间保留一个空格。原生选项与图文选择器的当前项、下拉项使用相同的间距；无群组时不添加群组前缀。

编辑界面和协作脚本每组保留至多一名超级管理员与一名普通管理员，两者可以共存；已有超级管理员时不强制把执行者提升为普通管理员。无任何管理角色时沿用普通管理员兜底。建队提示优先由超级管理员发起。持久化角色优先于名称推断，不随激活顺序变化；旧 `管理者`、`planner` 等别名继续兼容。

## 根因与回归

此前把超级管理员限定为 WebUI 登录身份，前端下拉未提供它，后端白名单也拒绝它；设置页回退和强刷均不能解决。旧测试还断言“不进入群组角色”，本次改为用户实际操作路径的正向回归。

- `tests/terminal-session-groups.test.mjs`：四角色映射、最高负责人、角色并存与兜底。
- `tests/terminal-session-groups.browser.py`：桌面及移动视口真实点击皇冠选项、保存载荷、重开回显（API 隔离模拟，不更改用户终端）。
- `src/terminal/manager.rs::terminal_super_admin_tests`：真实分组更新、序列化回读、普通管理员并存、拒绝无效角色。
- `tests/terminal-team-roles.test.py`：skill 合并保留角色、显式最高负责人、名称推断优先级。

后端改动经部署队列生效；静态资源更新不能代替后端发布。部署后需要核对请求回调、运行二进制及 HTTP 资源身份，再验证真实 API 保存及回读。
