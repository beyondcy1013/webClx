# FRP 角色管理边界

webClx 的 FRP 角色分为自身启动的进程和外部进程。外部进程通常由 systemd 或其他 supervisor 管理；发现其 PID 和配置文件只表示可以展示状态，不表示 webClx 拥有该进程的生命周期。

## 外部配置

- 首次接管外部配置只登记角色，不改写原文件。
- 后续从角色编辑器保存时，更新实际外部 TOML。
- 使用结构化 TOML 更新，仅覆盖 UI 支持的字段；保留未知顶层字段和同名代理中的未知字段。
- 写入必须先完成解析和渲染，再通过同目录临时文件原子替换。

## 进程所有权

- `start` 检测到同组件、同配置路径的外部进程时视为已经运行，不得重复启动。
- `stop` 和 `restart` 只能操作当前 `FrpRoleManager` 持有的子进程句柄。
- 对外部进程执行 `stop` 或 `restart` 必须拒绝，并提示使用对应的系统服务管理。
- webClx 自身创建的 FRP 子进程使用 kill-on-drop，避免管理器退出后遗留孤儿进程。

## 死锁回归

启动角色后，写入运行态所持有的互斥锁必须在调用 `status()` 前释放。`status()` 会再次访问同一运行态；持锁调用会形成自死锁。浏览器状态轮询随后会让更多 Tokio 工作线程阻塞在该同步锁上，最终可能使整个 HTTP 服务停止响应。

涉及持久子进程的测试必须使用 RAII 清理、测试内短超时和命令级硬超时，具体约束见仓库 `AGENTS.md`。
